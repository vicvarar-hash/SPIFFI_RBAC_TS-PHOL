% ABSTRACT
%==============================================================================
\begin{abstract}
\begin{sloppypar}
Autonomous LLM agents invoke external tools through the Model Context Protocol (MCP), opening an authorisation surface the protocol does not govern. We reframe agentic tool selection as an \emph{access-control} problem---\emph{semantic correctness is not authorisation correctness}: a benchmark-correct tool bundle may be inadmissible, and an incorrect one admissible---and contribute a \textbf{task-relational admission primitive} (TRAC) that authorises an invocation on the coherence between the task and its proposed action-set, as the final stage of an invocation-time pipeline (SPIFFE/SPIRE identity, RBAC, ABAC, TRAC). Around it we build a \textbf{measurement framework for layered authorisation}: a dual-mode protocol separating the LLM \emph{judging} a candidate bundle from \emph{generating} one, two metric conventions that disagree on layer importance, and paired bootstrap CIs on per-layer marginals. On ASTRA v0.3~\cite{elhelou2025astra} across six models and three vendors ($\sim$$114$K decisions), a deterministic policy floor bounds every model's composed worst case (SecFail $\leq 7.5\%$) beneath a model-invariant floor ($10.3\%$) that the same LLMs judging alone blow past ($27$--$67\%$); RBAC and TRAC each carry a large order-independent \emph{drop-one} marginal ($-20.7$/$-12.0$pp) while ABAC backstops RBAC; and first-firing attribution misranks layers. We are explicit about the envelope---the floor guards against \emph{semi-honest mis-scoping} only (adversarial task text evades its lexical predicates), at a bounded availability cost---$19.3\%$ over-block on \emph{admissible} (correct \emph{and} authorised) requests, correct-but-unauthorised least-privilege denials excluded---and claim no new rule-engine (verified OPA/Rego parity). All policies, logs, and analysis scripts are released.
\end{sloppypar}
\end{abstract}

\section{Introduction}
\label{sec:introduction}

\subsection{Motivation}
\label{sec:motivation}

LLM agents that autonomously select and invoke external tools have proliferated across enterprise and consumer domains~\cite{wang2024survey, xi2025rise}, building on tool-augmented language models~\cite{schick2023toolformer} and ReAct-style reasoning-and-acting loops~\cite{yao2023react}. They now standardise on the Model Context Protocol (MCP)~\cite{anthropic2024mcp} as the de facto tool-invocation interface. MCP deployments typically assume a trusted execution environment with no native identity verification, permission scoping, or deterministic predicate evaluation. The security gap is consequential: an agent tasked with ``investigating anomalous metrics'' might autonomously select tools that modify production alert rules, mutate database state, or initiate financial transactions far outside its intended mission. Recent analyses catalogue 16 MCP-lifecycle threat categories~\cite{gupta2025security} and document exploits including credential theft, tool poisoning, and remote code execution~\cite{jamshidi2025securing}.

Existing LLM-security work addresses fragments. Prompt-injection defences~\cite{liu2024formalizing, zhan2024injecagent} target adversarial reasoning manipulation; output filters such as Llama Guard~\cite{inan2023llamaguard} constrain generation content; agent-safety benchmarks~\cite{zhang2024agentsafetybench, yuan2024rjudge} evaluate behaviour in controlled environments. None reasons about the security properties of \emph{individual tool invocations} within a multi-domain operational context. Chu et al.~\cite{chu2026stateless} identify a layered attack-surface model but provide no enforcement mechanism; we instantiate one as a staged invocation-time pipeline.

This exposes a reframing the agentic-AC literature has largely missed: \emph{task-tool semantic correctness is not authorisation correctness}. A bundle a task-tool benchmark scores as ``correct''---the tools that best accomplish the task---may still be \emph{inadmissible} under the agent's role, attribute, and task-coherence constraints; conversely a benchmark-incorrect bundle may be perfectly admissible. Authorising agentic tool use is therefore an access-control problem, not a retrieval-accuracy one, and it needs an enforcement primitive that conditions on the task$\leftrightarrow$bundle relation---a predicate outside the \emph{conventional} attribute vocabulary of RBAC and ABAC, though (as we show, \S\ref{sec:substrate_portability}) expressible over \emph{derived} task-relational attributes on a standard policy engine.

\subsection{Contributions}
\label{sec:contributions}

Our primary contribution is an \emph{access-control} one: we recast agentic tool invocation as an authorisation problem (semantic correctness $\neq$ authorisation correctness) and introduce a \emph{task-relational} admission primitive (TRAC) that enforces it. Around this primitive we contribute a \emph{measurement methodology} for layered authorisation---quantifying how a deterministic policy stack and LLM judgement compose---realised in the PALADIN pipeline. We claim no novel rule-engine machinery (verified OPA/Rego parity, \S\ref{sec:substrate_portability}); the contributions are the primitive, the reframing, and the measurement framework around them. Concretely:

\begin{enumerate}
  \item A \textbf{methodology for measuring layered authorisation}: (a) a dual-mode validation/selection protocol separating ``the LLM judges a candidate bundle'' from ``the LLM generates one,'' which most task-tool benchmarks conflate; (b) two metric conventions (security- vs.\ permissivity-view) that systematically disagree on layer importance and must be reported jointly; (c) paired task-level bootstrap CIs on layer-marginal $\Delta\mathrm{SecFail}$; and (d) a dataset-ceiling analysis. That analysis places the practical exact-match upper bound at $30$--$40\%$, against which $39\%$ retrieval-augmented selection accuracy must be read (\S\ref{sec:methodology},~\ref{sec:conventions},~\ref{sec:ceiling}).

  \item A \textbf{task-relational admission primitive and its instantiation, PALADIN}: a predicate that authorises a tool invocation on the \emph{semantic coherence between the task and the proposed bundle}---in-domain coverage, mutation safety, and task--tool relevance---realised as the TRAC stage of an invocation-time pipeline (SPIFFE/SPIRE identity, RBAC, ABAC, fact extraction, and TRAC over an \emph{agnostic} $\{$domain$\}{:}\{$action$\}$ capability model). It conditions on the task$\leftrightarrow$bundle \emph{relation}---distinct from the workflow axis of TBAC~\cite{thomas1997tbac}, the entity-relationship axis of ReBAC~\cite{fong2011rebac}, and the \emph{declared}-purpose axis of Purpose-BAC~\cite{byun2005purpose} (TRAC conditions on \emph{measured} task--bundle coherence)---and is expressible only over \emph{derived} attributes that native RBAC/ABAC do not carry, supplied by a fact transformer (\S\ref{sec:related}). We claim no new access-control \emph{axis} in the expressiveness sense and no novel rule-engine: our OPA/Rego parity runs the identical rules-as-data with bit-identical decisions (\S\ref{sec:substrate_portability}). The pipeline consumes \emph{no ground-truth label}---the task domain is inferred from task text by BM25 (\S\ref{sec:domain_inference})---and every decision is recomputable from the released logs without further LLM calls.

  \item \textbf{A deterministic security floor---model-invariant by construction, and we measure what it buys}: because the deterministic stack conditions on the bundle, not the model, it returns a \emph{bit-identical} profile ($F_1\!=\!0.848$, SecFail $=10.3\%$) for every model; the empirical content is not the invariance but the floor's \emph{magnitude} and the residual it leaves for the model to close. LLM-only $F_1$ ranges over $0.28$ on the same inputs; composing the model's own verdict behind the floor sharpens SecFail to $2.1\%$ (gpt-4o) and never exceeds the floor for a weak judge: the policy bounds the worst case. A full blind cross-vendor panel---Claude Opus 4.8, Claude Sonnet 4.6, and Gemini 2.5 Pro on all $6{,}942$ rows---falls within the OpenAI LLM-only band, the composed pipeline converging to SecFail $\leq\!7.5\%$ across three vendors (\S\ref{sec:stack_guarantee},~\ref{sec:cross_vendor},~\ref{sec:newer_not_better}).

  \item \textbf{Complementary layers, measured two ways}, with paired CIs: the order-independent \emph{drop-one} marginals are $-20.7$pp (RBAC) and $-12.0$pp (TRAC)---each individually load-bearing---while ABAC's is only $-0.9$pp because it \emph{overlaps} RBAC, yet ABAC is load-bearing when RBAC is absent (successive $-23.4$pp). TRAC's isolated $-12.0$pp is direct evidence the task-relational predicate catches violations conventional RBAC$+$ABAC do not on this benchmark---and under a label defined independently of every policy artefact it becomes the \emph{largest} marginal (\S\ref{sec:reversal})---while the successive/drop-one gap exposes a first-firing attribution pitfall (\S\ref{sec:per_domain}).

  \item \textbf{Attribution paradox, corroborated coverage, and an RA-ICL safety result}: (a) first-firing denial attribution misleads---RBAC claims $82\%$ of denials, yet ABAC (claiming $4\%$) carries the \emph{largest} successive marginal ($-23.6$pp)---a pitfall in much of the agent-safety literature; (b) \emph{corroborated coverage} recovers legitimate work at near-zero security cost; and (c) BM25 RA-ICL yields a paired-cohort security \emph{improvement} ($\Delta\mathrm{SecFail}\!=\!-0.064$, CI excludes zero). We also reproduce ASTRA's LLM-ResM~\cite{elhelou2025astra} under a stricter per-bundle protocol (\S\ref{sec:attribution_paradox},~\ref{sec:corroborated},~\ref{sec:raicl}).
\end{enumerate}

\noindent\textbf{What this paper is not.} PALADIN governs invocation-time authorisation and is a security-first floor, not an end-to-end agent-security solution. Prompt-injection defences, tool-output exfiltration, MCP supply-chain, and side-channel attacks are out of scope and intended to compose with PALADIN (\S\ref{sec:deployment_envelope}).

\section{Related Work}
\label{sec:related}

\subsection{Access Control, Policy Languages, and Task-Tool Benchmarks}
\label{sec:access_control}

Five decades of access-control foundations span lattice models~\cite{bell1973secure}, RBAC~\cite{sandhu1996role,ferraiolo2001proposed}, ABAC~\cite{hu2014guide}, and policy languages with decidable analysis (Cedar~\cite{cutler2024cedar}, XACML~\cite{oasis2013xacml}, Margrave~\cite{fisler2005verification}). These were designed for human principals on static boundaries; agents construct invocations dynamically via probabilistic reasoning, span multiple domains per task, and produce confidence scores carrying security-relevant signal.

Two AC lineages model structure beyond the subject and are the natural reference points for a ``task-relational'' claim. \emph{Task-Based Access Control} (TBAC)~\cite{thomas1997tbac} ties permission \emph{activation} to a task's workflow lifecycle---permissions are granted and revoked just-in-time as a task advances through its steps. \emph{Relationship-Based Access Control} (ReBAC)~\cite{fong2011rebac} authorises on \emph{relationships among entities} (owner-of, member-of, $\dots$). Our task-relational predicate is orthogonal to both: it gates on the \emph{semantic coherence between the task's intent and the proposed tool bundle}---is this bundle in-domain and sufficient for what the task asks?---not on a workflow position (TBAC) or an entity graph (ReBAC). It is complementary, not a replacement: an agent could be scoped by TBAC over a workflow \emph{and} checked by a task-relational coverage predicate at each invocation. Two further lineages sharpen the comparison: \emph{Purpose-Based Access Control}~\cite{byun2005purpose} authorises by the declared \emph{purpose} of an access, and \emph{Usage Control} (UCON)~\cite{park2004ucon} unifies authorisations, obligations, and conditions over mutable attributes with continuity of enforcement. TRAC differs in \emph{what} it conditions on: a \emph{measured} coherence between the task text and the proposed bundle, computed at invocation time from public tool descriptions---not a self-declared purpose label (which the semi-honest agent controls) nor an obligation model---and it composes with, rather than replaces, either.

Relative to Cedar and HashiCorp Sentinel---the substrates most often proposed for agentic authorisation---TRAC adds (i) typed predicates over LLM-emitted continuous confidence/trust scores with thresholds revisable as policy, (ii) a \emph{task-relational} coverage predicate---whether the proposed bundle covers the inferred task domain---conditioning on the task$\leftrightarrow$bundle relation rather than on caller or resource attributes alone, and (iii) bundle-level decision points composing over the full emitted tool set. We \emph{do} provide a head-to-head OPA/Rego re-implementation: the RBAC, ABAC, and TRAC layers run as rules-as-data on a standard Open Policy Agent runtime with decisions verified bit-identical to our reference engine (\S\ref{sec:substrate_portability}). This confirms our novelty is the task-relational \emph{predicate} and the measurement framework, not the rule engine---which is substrate-portable.

The closest task-tool benchmark is ASTRA~\cite{elhelou2025astra}, whose LLM reasoning matcher (LLM-ResM, per-tool GPT-4o with AND-aggregation) reports $F_1\!\approx\!0.67$ on the $N\!=\!3$ multi-tool test split. We re-use ASTRA's corpus and labels, reproduce LLM-ResM under a stricter per-bundle protocol (\S\ref{sec:astra_replication}), and evaluate what a deterministic stack composed on top achieves on the same inputs.

\subsection{Zero-Trust, Agent Identity, and MCP Security}
\label{sec:zero_trust}
\label{sec:agent_safety}

NIST Zero Trust~\cite{rose2020zero} and SPIFFE~\cite{spiffe2022} establish cryptographic workload identity but have not been applied to AI-agent identity; recent delegation work~\cite{south2025authenticated,rampalli2026pedigree} and defence-in-depth surveys~\cite{chu2026stateless,jangam2024comprehensive,muhammad2024integrative} map the layered attack surface without providing formal enforcement.

The agent-safety community has produced evaluation frameworks---Agent-SafetyBench~\cite{zhang2024agentsafetybench}, ToolEmu~\cite{ruan2024toolemu}, GuardAgent~\cite{xiang2024guardagent}, R-Judge~\cite{yuan2024rjudge}, ALMITA~\cite{arcadinho2024almita}, Constitutional AI~\cite{bai2022constitutional}, deceptive-alignment analyses~\cite{hubinger2024sleeper}---and prompt-injection defences~\cite{liu2024formalizing,zhan2024injecagent,debenedetti2024agentdojo,kim2025promptflow,inan2023llamaguard}. These treat the agent monolithically and do not enforce authorisation at the invocation boundary. MCP-specific work has begun mapping the landscape (16 threat categories~\cite{gupta2025security}, practical exploits~\cite{jamshidi2025securing}, cross-server tool poisoning~\cite{invariantlabs2025toolpoisoning}); multi-agent and behavioural-trust efforts~\cite{patil2026sentinelagent,schroederdewitt2025open,xu2025master,wu2023autogen,rao1995bdi,csa2025fortifying,cisco2025redefining} establish the problem space but offer ad-hoc rather than staged enforcement. Foundational tool-augmented architectures~\cite{schick2023toolformer,yao2023react,wang2023voyager,wang2024survey,xi2025rise} provide the agents but no governance for their invocations; PALADIN is architecture-agnostic and composes on top.

\section{System Architecture}
\label{sec:architecture}

\subsection{Pipeline Overview}
\label{sec:pipeline_overview}

The Unified Decision Engine executes six sequential stages with short-circuit semantics: any \texttt{DENY} from stages S1--S4 terminates the pipeline immediately (Figure~\ref{fig:pipeline}). S5 extracts typed facts; S6 (TRAC) consumes them for predicate-level evaluation.

The deterministic stages are model‑independent; the LLM verdict gate composes \emph{conjunctively} with the deterministic floor (its drawn position is presentational---FULL $=$ floor $\wedge$ verdict) and is present only in validation, while in selection the LLM instead generates the bundle.}

\subsection{Evaluation State and Short-Circuit Semantics}
\label{sec:state_model}

Each stage records \texttt{ALLOW}, \texttt{DENY}, or \texttt{NOT\_EVALUATED}; the final decision is the conjunction of evaluated stages. A \texttt{DecisionResult} carries the per-stage map, final decision (\texttt{ALLOW}/\texttt{DENY}), denial source, and audit trace. Short-circuiting yields three benefits: computational efficiency (S6 is skipped when cheaper checks suffice), security hardening (later stages cannot mask upstream denials), and audit clarity (the denial source unambiguously identifies the triggering concern).

Beyond the per-stage states, the pipeline returns a single binary admission decision: $\Pi(r)=\text{ALLOW}$ only if every evaluated stage allows, and $\text{DENY}$ otherwise. There is no third outcome---a denied high-risk write simply stays \texttt{DENY}---which keeps every layer expressible as a standard ALLOW/DENY policy (\S\ref{sec:substrate_portability}). Advisory TRAC rules (\S\ref{sec:trac}) may additionally raise non-blocking alerts on an admitted bundle, but these never change the admission decision and are excluded from the security metrics.

\subsection{Threat Model and Deployment Envelope}
\label{sec:threat_model}

\textbf{Adversary.} A \emph{semi-honest agent}: an authenticated LLM-driven workload that, given an operator- or workflow-supplied task, may select and emit a tool bundle that exceeds scope, crosses domains, targets writes without prior reads, or otherwise violates policy---through hallucination or over-helpful, helpfulness-optimised behaviour. It controls the \emph{emitted bundle}; the task text is trusted provenance (operator/workflow), which is what makes the task-relational predicates meaningful. Active manipulation of the task text itself---prompt injection \emph{into the task}, crafted to steer the BM25 predicates---is out of scope and composes with the prompt-injection defences of \S\ref{sec:deployment_envelope}.

\textbf{Trust assumptions.} We trust the SPIFFE/SPIRE identity substrate, policy YAML/JSON integrity at load, the MCP tool registry, and the deterministic pipeline; we do \emph{not} trust LLM-emitted bundles, confidence scores, or natural-language justifications.

\textbf{In-scope.} Within-domain mis-scoping, cross-domain capability leakage, mutation-without-read, hard-capability gaps, and trust-state misalignments (operationalised by ASTRA's \texttt{wrong}/\texttt{null} negatives). \textbf{Out of scope:} policy-file compromise, side channels, DoS, MCP supply-chain attacks, active adversarial prompts crafted to evade specific predicates, and tool-output exfiltration. \textbf{Security objective:} minimise SecFail (Eq.~\ref{eq:secfail}) subject to a bounded false-block rate on legitimate requests; the trade-off point is set by policy, not architecture.

\textbf{Deployment envelope.} PALADIN is an invocation-time authorisation layer, not an end-to-end agent-security solution. The exclusions above are not minor: each is an active research area, and production deployment composes PALADIN with output filters (e.g., Llama Guard~\cite{inan2023llamaguard}), signed registries, network-layer rate limiting, and prompt-injection defences~\cite{liu2024formalizing}. Contribution claims are scoped to that envelope. In particular, because TRAC's two enforcing predicates are computed by BM25 over the task text, an adversary who \emph{crafts} task text to lexically match a target bundle can defeat the deterministic floor; its security value is therefore a bound on \emph{semi-honest} mis-scoping---hallucination, over-helpfulness, and benign scoping errors (ASTRA's non-adversarial \texttt{wrong}/\texttt{null} negatives)---not on active task-text manipulation, which requires trusted task provenance and the composed prompt-injection controls above.


\section{Mathematical Framework}
\label{sec:framework}

\subsection{Request Model and Short-Circuit Composition}
\label{sec:request_model}
\label{sec:composition}

A tool invocation request is modelled as a 6-tuple
\begin{equation}
r = \langle \iota, \tau, T, M, c, \delta \rangle
\label{eq:request}
\end{equation}
where $\iota$ is the agent identity (SPIFFE ID), $\tau$ the task description, $T=\{t_1,\dots,t_n\}$ and $M=\{m_1,\dots,m_n\}$ the selected tools and their MCP servers, $c\in[0,1]$ the LLM confidence, and $\delta$ the environmental context (timestamp, compliance tier).

The short-circuit composition operator $\rhd$ between stages is
\begin{equation}
\begin{aligned}
(S_i \rhd S_j)(r) &= \\
&\begin{cases}
\text{DENY}_i, & \text{if } S_i(r) = \text{DENY}, \\
S_j(r), & \text{otherwise.}
\end{cases}
\end{aligned}
\label{eq:composition}
\end{equation}
$S_5$ is not a decision stage but a deterministic \emph{fact-transformer} $\phi\!:\!r\!\mapsto\!\Phi(r)$ that materialises the typed fact base consumed by $S_6$; it cannot return DENY. The full pipeline is therefore
\begin{equation}
\Pi(r) = \bigl(S_1 \rhd S_2 \rhd S_3 \rhd S_4 \rhd S_6\bigr)\!\bigl(r,\phi(r)\bigr),
\label{eq:pipeline}
\end{equation}
i.e. $\phi$ runs once when $S_1$--$S_4$ all admit, and $S_6$'s predicates evaluate over $\Phi(r)$.

\subsection{Stage Definitions}
\label{sec:stage_definitions}

\textbf{S1--S2} are deterministic set-membership checks: $S_1$ admits iff $\iota \in \mathcal{I}_{\text{valid}}$, and $S_2$ admits iff every $t\in T$ is in the registry $\mathcal{R}(m_t)$. \textbf{S3 (RBAC)} evaluates role-based permissions:
\begin{equation}
S_3(r) = \begin{cases}
\text{ALLOW} & \text{if } \forall (m_j, t_j) \in \text{zip}(M,T)\!: (m_j, t_j) \in \rho(\iota) \\
\text{DENY} & \text{otherwise}
\end{cases}
\label{eq:rbac}
\end{equation}
where $\rho(\iota)$ maps an identity to its permitted (domain, tool) pairs. \textbf{S4 (ABAC)} implements first-match semantics over attribute conditions,
\begin{equation}
S_4(r) = \text{first-match}(\mathcal{P}_{\text{ABAC}}, \text{attrs}(r)),
\label{eq:abac}
\end{equation}
with $\mathcal{P}_{\text{ABAC}}$ the ordered policy set and $\text{attrs}(r)$ extracting subject, resource, action, and environment attributes. \textbf{S5} is the fact-transformer $\phi$ of Eq.~\ref{eq:pipeline}: it derives typed facts without making any decision. \textbf{S6 (TRAC)} evaluates typed predicates over $\Phi(r)$:
\begin{equation}
S_6(r) = \begin{cases}
\text{DENY} & \text{if } \exists\, R_i \text{ s.t. } \text{triggered}(R_i) \land a_i = \text{DENY} \\
\text{ALLOW} & \text{otherwise.}
\end{cases}
\label{eq:trac}
\end{equation}

\subsection{Agnostic Capability Coverage}
\label{sec:capability}
\label{sec:alignment}

TRAC's capability model is deliberately \emph{agnostic}: a capability is the pair $\{d\}{:}\{a\}$, where $d$ is the MCP a tool belongs to and $a\in\{\textrm{read},\textrm{write}\}$ is its action class, with the subsumption rule that a write also grants the read ($\{d\}{:}\textrm{write}\sqsupseteq\{d\}{:}\textrm{read}$). There is no per-MCP vocabulary, no capability catalog, and no curated tool$\to$capability map: the bundle's provided capabilities are $\mathrm{HasCap}=\{\{d(t)\}{:}\{a(t)\}\mid t\in T\}$, derived mechanically from each tool's MCP and its read/write class (\S\ref{sec:layers}). Coverage is domain-only: the required capability for a task with inferred domain $d_\tau$ is the action floor $\{d_\tau\}{:}\textrm{read}$---any in-domain tool, read or write, satisfies it---and a hard violation is
\begin{equation}
\mathrm{HardCapMissing}(r)\;\triangleq\;\{d_\tau\}{:}\textrm{read}\notin\mathrm{HasCap}.
\label{eq:hardcap}
\end{equation}
We deliberately do \emph{not} infer read-vs-write \emph{intent} from task text, nor gate on a weighted alignment score: those heuristics were substring-fragile and, for the domain signal, oracle-dependent. Mutation concerns are owned by the \texttt{write\_safety} advisory and lexical task--bundle fit by \texttt{tool\_relevance} (\S\ref{sec:trac}). $d_\tau$ itself is inferred from the task text alone (\S\ref{sec:domain_inference}), so the entire coverage check is free of any ground-truth label. This is a property RBAC (caller$\to$tool) and ABAC (attributes) do not express in their conventional vocabulary: whether the proposed bundle is coherent with the task's domain---expressible, as we show, over derived attributes on a standard engine (\S\ref{sec:substrate_portability}).

\subsection{Security Metrics and Composition Properties}
\label{sec:security_metrics}
\label{sec:composition_properties}

We report
\begin{align}
F_1 &= \frac{2\,\text{TP}}{2\,\text{TP} + \text{FP} + \text{FN}} \label{eq:f1} \\
\text{SecFail} &= \frac{\text{FN}}{\text{TP} + \text{FN}} \label{eq:secfail}
\end{align}
Layer contribution is the subtractive ablation $\Delta_{\text{metric}}(S_k)=\text{metric}(\Pi)-\text{metric}(\Pi\setminus S_k)$, applied uniformly to $F_1$ and SecFail. Under this convention a layer that \emph{adds} security yields $\Delta F_1(S_k)>0$ and $\Delta\mathrm{SecFail}(S_k)<0$ (because removing the layer raises SecFail). The same sign convention is used in all per-layer tables and in \S\ref{sec:methodology}.

The operator $\rhd$ gives $\Pi$ three properties. \textbf{(P1) Monotonicity:} adding a stage can only convert ALLOW to DENY (immediate from the short-circuit semantics). \textbf{(P2) Order-independence of unique necessity:} if a single $S_k$ is the only stage that would deny $r$, $\Pi(r)=\mathrm{DENY}$ regardless of ordering. \textbf{(P3) Fail-secure default:} predicates default conservatively on missing facts and stage exceptions are wrapped to DENY, so partial failure cannot silently degrade to ALLOW. P1 grounds the $\Delta$-value reading; P2 underpins the attribution analysis (\S\ref{sec:attribution_paradox}).

\section{Security Layers and Predicate Derivation}
\label{sec:layers}

\subsection{RBAC, ABAC, and Tool Classification}
\label{sec:rbac_abac_classification}

\textbf{Agent-adapted RBAC} maps agent personas to permissions over tool bundles across MCP domains, with three adaptations from traditional RBAC: tool-level granularity (per individual tool rather than per service endpoint); wildcard domain grants for trusted agents (e.g., \texttt{grafana.*}); and cross-domain permission intersection requiring permissions in \emph{all} referenced domains across dynamically-constructed multi-tool bundles.

\textbf{ABAC} first-matches an ordered rule set over the subject, resource, action, and environment attributes of the request (\S\ref{sec:stage_definitions}). The released ruleset contains $6$ rules in three families, conditioning on \emph{subject} (department, clearance level, trust score), \emph{resource} (compliance tier, data sensitivity, risk level), and \emph{action} (write, destructive-write) attributes: \emph{department/compliance isolation} (Financial/PCI-DSS resources restricted to Finance; Infrastructure writes to Engineering or Infrastructure), \emph{clearance gates} (L2 to read high-risk resources, L3 to write them, L3 for destructive operations), and a \emph{trust gate} (trust score $\geq 0.8$ to write). A rule denies when all its conditions hold; conditions fail closed on an absent attribute; the request is denied if any rule fires.

\textbf{Action classification.} Each tool's action class $a(t)\in\{\textrm{read},\textrm{write}\}$ (with \texttt{destructive} a write subtype) is derived deterministically from only the two universally-available MCP fields---the tool \emph{name} and \emph{description}---by a verb lexicon grounded in established lexical-semantic verb classes (Levin/VerbNet and the corresponding FrameNet frames) mapped onto the read/write/destructive safety taxonomy (CRUD; RFC~9110 safe/unsafe methods; MCP \texttt{ToolAnnotations}). The leading description verb is lemmatised and class-mapped, ambiguous verbs are read-guarded (e.g.\ \emph{run/execute a query} $\to$ read), and the tool name is fused escalate-only toward write/destructive, realising the principle of fail-safe defaults. There is no curated per-tool label map. Request-level predicates follow by composition---$\text{ContainsWrite} = \bigvee_{t \in T} (a(t)=\texttt{write})$, and analogously $\text{ContainsDelete}$ and $\text{ContainsRead}$---and become typed inputs to TRAC.

\textbf{Agnostic capability.} The capability a tool provides is the pair $\{d(t)\}{:}\{a(t)\}$ of \S\ref{sec:capability}---its MCP domain $d(t)$ and the action class $a(t)$ above---with the subsumption $\{d\}{:}\textrm{write}\sqsupseteq\{d\}{:}\textrm{read}$. There is \emph{no} capability catalog, entailment ontology, or hard/soft capability tier: coverage is the single domain floor of Eq.~\ref{eq:hardcap}, evaluated against the BM25-inferred task domain (\S\ref{sec:domain_inference}), while mutation- and relevance-level concerns are delegated to the \texttt{write\_safety} and \texttt{tool\_relevance} rules (\S\ref{sec:trac}). The model therefore consumes no per-MCP vocabulary, no curated tool$\to$capability map, and no ground-truth label---the property that makes the pipeline leak-free.

\subsection{TRAC: an ordered, typed production rule engine}
\label{sec:trac}

TRAC (Task-Relational Access Control) conditions the admission decision on the \emph{relation between the task and the proposed tool bundle}---in-domain coverage, mutation safety, and task--tool relevance---which conventional RBAC (caller$\to$tool) and ABAC (subject/resource attributes) do not express, and which is distinct from the workflow-lifecycle axis of TBAC~\cite{thomas1997tbac} and the entity-relationship axis of ReBAC~\cite{fong2011rebac} (\S\ref{sec:related}). We are explicit about what this is \emph{not}: not a new access-control axis in the expressiveness sense, and not novel rule-\emph{engine} machinery---the identical rules-as-data run bit-identically on OPA/Rego (\S\ref{sec:substrate_portability}), so TRAC is a \emph{derived-attribute predicate} over a commodity engine. The scientific contribution is the specific leak-free predicate and the measurement framework. The engine's expressive content is equivalent to a typed Cedar~\cite{cutler2024cedar} or OPA/Rego extension with custom builtins for continuous LLM-emitted scores; an OPA/Rego re-implementation evaluating the identical rules-as-data reproduces every decision on a standard OPA runtime (\S\ref{sec:substrate_portability}), so only the \emph{performance} cost of the substrate remains to be benchmarked. The remaining scientific contributions are the measurement framework and the empirical findings. The engine has four properties: \emph{typed} (a fixed-signature schema of booleans, enums, and reals); \emph{staged} (facts are derived in $\phi=S_5$ before any $S_6$ rule fires, so evaluation is a pure function of the fact base and policy text); \emph{ordered} (enforcing rules fire in policy-declared order and short-circuit on the first denial, making the decision a total function of $\Phi(r)$ and policy text); and \emph{partitioned} into \emph{enforcing} rules that change the ALLOW/DENY decision and \emph{advisory} alert-only rules that only write to the audit trail (both grouped in Table~\ref{tab:trac_rules}). Evaluation is $O(n)$ in the rules given pre-computed facts; RBAC, ABAC, and TRAC evaluate independently.

These four rules instantiate TRAC concretely; they are declarative data, so an operator can retune thresholds or add rules without touching the engine. The two enforcing rules gate admission: \texttt{capability\_coverage} denies a bundle when none of its tools operates in the task's domain---inferred from task text alone, so the check reads no ground-truth label (\S\ref{sec:domain_inference}) and softened by \emph{corroborated coverage} (\S\ref{sec:corroborated})---while \texttt{tool\_relevance} denies a bundle whose tools have low lexical (BM25) overlap with the task. The two advisory rules only annotate the audit trail: \texttt{write\_safety} on a destructive operation lacking a verifying read, and \texttt{action\_coherence} on a read-only-sounding task that selected mutating tools. All are fail-secure and deterministic---predicates default conservatively on missing facts, and identical facts yield identical, individually-explained decisions---and the set is illustrative rather than exhaustive: further task-relational predicates compose in the same typed, ordered form.

\paragraph{Engine portability.} The feature set S6 exercises---typed continuous LLM-emitted scores, derived predicates as first-class rule inputs, ordered short-circuit denial with auditable triggered-rule trails, and a fixed pre-rule fact-derivation stage---is not exotic: each is native or a standard extension away in commodity policy engines (Cedar extension functions, OPA/Rego builtins and modules, Sentinel imports), none of which ships the full set out of the box. We therefore treat the engine as interchangeable and verify it directly---an OPA/Rego re-implementation of the identical rules-as-data reproduces every decision on a standard runtime (\S\ref{sec:substrate_portability}), so the substrate choice changes none of the empirical findings, and a Cedar port plus a performance benchmark are the remaining follow-ups.

PALADIN uses cryptographic agent identity (SPIFFE/SPIRE) as the source of $\iota$ in the request tuple (\S\ref{sec:request_model}); identity is an \emph{input} to the policy stack, not itself a contribution we evaluate. \section{Experimental Methodology}
\label{sec:methodology}

\subsection{Dataset, Personas, and Model Panel}
\label{sec:dataset}
\label{sec:model_panel}

We evaluate on ASTRA v0.3~\cite{elhelou2025astra}, a public corpus of $1{,}157$ agentic task-tool matching tasks across $8$ MCP server domains ($194$ tools: grafana, atlassian, azure, mongodb, stripe, notion, hummingbot, wikipedia), evaluated under six personas (DevOps L3, Incident L2, Finance L2, Research L1, Automation Gateway L3, Security Engine L3) whose SPIFFE IDs, clearance, and trust scores are released with the artefact.

The model panel spans three OpenAI generations: \textbf{gpt-3.5-turbo-16k} (2023), \textbf{gpt-4o} (2024-05; ASTRA's reference model, enabling direct replication), and \textbf{gpt-5.4} (2026, via Microsoft Azure AI Foundry). All inference uses temperature $0.0$, JSON-schema-constrained output, and a single retry on parse failure; no system prompt beyond the documented PALADIN protocol is injected. We treat this OpenAI panel as a within-lineage capability span, complemented by a full cross-vendor panel across Anthropic and Google in \S\ref{sec:cross_vendor}; open-weights models (Llama, Mistral) remain deferred (\S\ref{sec:future_work}).

\subsection{Dual-Mode Evaluation}
\label{sec:dual_mode}

Each (task, persona) row is evaluated under one of two modes; row identifiers are shared across modes so that paired comparisons are well-defined.

\textbf{Validation mode.} The LLM is given the task text \emph{together with} a candidate tool bundle and emits a JSON verdict (\texttt{validation\_failed} plus issue codes). The LLM judges, not selects. Candidate bundles carry an ASTRA \texttt{match\_tag}: \texttt{correct} ($3{,}474$ benchmark-correct rows after $\times 6$ personas), \texttt{wrong} ($2{,}778$, same-MCP wrong tools---hard within-domain negatives), and \texttt{null} ($690$, unrelated-MCP bundles---gross cross-domain negatives). The $80/20$ wrong/null mix is a property of ASTRA's construction. Total: $6{,}942$ rows per run.

\textbf{Selection mode.} The LLM is given the task text \emph{only} and must \emph{generate} a tool bundle as a JSON list, which is then routed through the same deterministic pipeline. Selection is strictly harder: under gpt-5.4, tool exact-match is only $11.4\%$ baseline, and the full deterministic stack moves from $F_1=0.848$ (validation E1) to $0.800$ (selection E1) but at a much higher SecFail ($10.3\%\!\to\!21.9\%$), because the model actively chooses same-domain wrong-tool bundles the agnostic stack cannot separate. We evaluate selection on $6{,}942$ rows in baseline and $4{,}512$ rows when retrieval is enabled (see below).

\subsection{Retrieval, Ablations, and Evaluation Conventions}
\label{sec:raicl_method}
\label{sec:ablation_design}
\label{sec:conventions}
\label{sec:eval_metrics}

\textbf{RA-ICL.} For selection mode we additionally evaluate a BM25 retrieval-augmented variant. The exemplar pool is the $405$ \texttt{correct}-tagged task fingerprints from a fixed $70/30$ task-level split (\texttt{correct\_70\_30\_seed42\_v2.json}); the retriever is BM25 (Okapi, $k_1\!=\!1.5$, $b\!=\!0.75$) over task text, with exact-match exemplars excluded per query. The evaluation cohort excludes the $405$ training fingerprints and consists of $174$ \texttt{correct}-test, $463$ \texttt{wrong}, and $115$ \texttt{null} fingerprints $\times$ $6$ personas $= 4{,}512$ rows. We test only the BM25 feature (denoted ``+C'') on gpt-5.4; +A (RBAC-scoped catalog) and +B (capability pre-filter) are reserved for future work.

\textbf{Ablations.} Four experiments per (model, mode): \textbf{E1} full stack (RBAC+ABAC+TRAC), \textbf{E2} $-$RBAC, \textbf{E3} TRAC only, \textbf{E4} LLM verdict only (direct comparison to ASTRA's LLM-ResM; only meaningful in validation since selection-E4 degenerates to allow-all). Each (model, mode) row is evaluated once---recording the independent per-layer states---and the four ablation views E1--E4 are derived offline from those states. Corpus: three OpenAI validation models and six selection configurations over $6{,}942$ rows each (the BM25 RA-ICL conditions on a smaller cohort), $\approx 114{,}000$ policy decisions in all, plus a full three-model non-OpenAI validation panel (\S\ref{sec:cross_vendor}).

\textbf{Two conventions.} Prior work uses different "positive" classes. \emph{Convention~A (PALADIN security view)}---positive $=$ illegitimate request: \texttt{is\_legitimate} iff \texttt{match\_tag}$=$\texttt{correct} \emph{and} persona $\in$ \texttt{LEGITIMATE\_PAIRINGS}; SecFail$=$FN/(TP+FN) is the probability a true violation escapes. Default throughout. \emph{Convention~B (ASTRA permissivity view)}---positive $=$ legitimate, with \texttt{wrong}+\texttt{null} pooled as negative. Used only for the apples-to-apples ASTRA replication in \S\ref{sec:astra_replication}.

\textbf{Metrics.} We report Precision, Recall, $F_1$, SecFail, and---since a benchmark-correct request may itself be legitimately \emph{unauthorised}---two availability measures: the \emph{domain-level false-block rate} (legitimate, benchmark-correct requests denied; Convention~A) and the \emph{over-block rate on admissible requests} (both correct \emph{and} authorised), which isolates the true availability cost from correct least-privilege denials (\S\ref{sec:policy_dependence}). Per-layer marginals follow the $\Delta_{\text{metric}}$ ablation convention of \S\ref{sec:security_metrics} ($\Delta F_1\!>\!0$ and $\Delta\mathrm{SecFail}\!<\!0$ both mean the layer improves security), with $\Delta_{\mathrm{RBAC}},\Delta_{\mathrm{ABAC}},\Delta_{\mathrm{TRAC}}$ the successive E1$\to$E4 differences. Selection-mode tool quality reports Exact Match and Jaccard on the \texttt{correct} slice (\texttt{wrong}/\texttt{null} have no defensible gold bundle). \textbf{Label independence.} The positive class combines ASTRA's \texttt{match\_tag} with the persona--domain allow-list, and that allow-list is \emph{also} the source of the RBAC grants---so RBAC's cross-domain denials coincide with the label's domain criterion by construction. Two facts bound this: the independent signal is ASTRA's \texttt{match\_tag} (\texttt{correct}/\texttt{wrong}/\texttt{null}), authored by no policy layer; and re-authoring RBAC independently of the label preserves a material RBAC marginal while shifting the remainder onto TRAC/ABAC (\S\ref{sec:reversal}), so the layer conclusions are not label artefacts.

\textbf{Reproducibility.} All thresholds were fixed \emph{ex ante} (config commit hash recorded with the artefact, \S\ref{sec:artifacts}); the operating point of \S\ref{sec:stack_guarantee} emerges from the composition of predicate-level cutoffs, not any single confidence-gated rule. Zero unrecoverable inference failures across the OpenAI-panel rows. Raw per-row logs, the BM25 retriever, the splits file, and analysis scripts are released.

\subsection{Leak-Free Domain Inference}
\label{sec:domain_inference}

The agnostic capability check (\S\ref{sec:capability}) requires the task's domain $d_\tau$. We infer it \emph{from the task text alone}, consuming no ground-truth field: each MCP server's tool names and descriptions form one BM25 document, the task text is the query, and $d_\tau$ is the top-scoring domain among the deployment's RBAC-entitled MCPs---or \texttt{uncertain} when the top two scores fall within $15\%$, in which case coverage abstains rather than deny on a coin-flip. This closes the only oracle dependency in the pipeline. An earlier configuration substituted the gold MCP (\texttt{gt\_mcps[0]}) as a stand-in for operator-supplied workflow context; the present task-text inference removes that substitution entirely, so neither \texttt{match\_tag}, \texttt{is\_legitimate}, nor any gold tool or domain reaches a decision path. The same inference runs identically in the batch harness and the live single-request path, so a single prediction and a batch replay reach the same verdict. Inference is intentionally imperfect ($\sim\!60$--$70\%$ top-1 on ASTRA), which is the honest cost of forgoing the oracle; when the inferred domain is wrong but the selected tools are strongly task-relevant, corroborated coverage (\S\ref{sec:corroborated}) recovers the denial.

\subsection{The Deterministic Stack Masks Model Variance Across Vendors (Validation)}
\label{sec:stack_guarantee}
\label{sec:cross_vendor}

PALADIN is deployed as the composition FULL $=$ the model's own verdict \emph{behind} the deterministic floor; it complements the LLM rather than replacing it. Table~\ref{tab:stack_guarantee} reads that composition across six models spanning three vendors, each judging every candidate bundle \emph{blind} to the ground-truth \texttt{match\_tag}/\texttt{is\_legitimate} with the \emph{same} \texttt{ValidationService} rubric (verdicts frozen before scoring and released). Each LLM judging \emph{alone} (E4) is an unreliable admission control---SecFail spans $26.8\%$ (gpt-4o) to $66.5\%$ (gpt-5.4), an $F_1$ spread of $0.28$, with the non-OpenAI models interleaved throughout ($0.49$--$0.63$) and no ordering by vendor or recency---yet the same LLM behind the floor (FULL) is sharpened to SecFail $\leq 7.5\%$ for all six. What makes the composition trustworthy is the floor beneath it: reported alone (E1), the deterministic stack (RBAC$\wedge$ABAC$\wedge$TRAC) returns an \emph{identical} profile for every model ($F_1=0.848$, SecFail $=10.3\%$, over-block $19.3\%$ on admissible requests), because the deterministic layers condition only on the bundle, persona, and leak-free inferred domain---never on the model---returning bit-identical decisions whichever LLM authored the verdict. This invariance is definitional, not a discovery; the substance is the floor's \emph{magnitude} ($10.3\%$ SecFail) and that it \emph{bounds} every model's composed result.

The floor is \emph{leak-free}: the task domain driving \path{capability_coverage} is inferred from task text by BM25 over the public MCP catalog (\S\ref{sec:domain_inference}), consuming no ground-truth label. That is why E1 sits at $10.3\%$ rather than zero---the agnostic stack still admits same-MCP wrong-tool bundles (ASTRA's \texttt{wrong} class) that no domain- or relevance-level signal separates from correct ones: the irreducible \emph{semantic floor} the model, not the policy, must close, which is the work the verdict gate does in FULL. Crucially, because FULL $=$ E1 $\wedge$ verdict is a conjunction it can only \emph{add} denials, so $\mathrm{SecFail}(\text{FULL})\leq\mathrm{SecFail}(\text{E1})$ \emph{by construction} (P1, \S\ref{sec:composition}): a capable judge (gpt-4o) sharpens SecFail to $2.1\%$, and even a useless one cannot lift FULL above the floor's $10.3\%$, whereas the LLM alone reaches $66\%$. Composing also collapses the cross-vendor E4 spread to $F_1\in[0.850,0.880]$, SecFail $\in[0.021,0.073]$. This is the central trade---an agnostic, leak-free floor, model-invariant by construction, sharpened but never undermined by the model---now shown across OpenAI, Anthropic, and Google.

\subsection{Substrate Portability: Verified OPA/Rego Parity}
\label{sec:substrate_portability}

The guarantee is a property of the \emph{policy}, not our particular engine. PALADIN's RBAC, ABAC, and TRAC layers are authored as \emph{rules-as-data}: the same YAML documents (\texttt{policies/\{rbac,abac\_rules,trac\_rules\}.yaml}) are evaluated both by our reference Python engine and, \emph{unchanged}, by generic Rego policies on a standard Open Policy Agent runtime (OPA v1.18.0). Editing a rule updates both; no code is generated or hand-synced. We verify decision equivalence with the real \texttt{opa} binary: across $120$ RBAC, $120$ ABAC, and $100$ unique-bundle TRAC evaluations, OPA reproduces \emph{every} ALLOW/DENY decision and every advisory of the reference engine---zero mismatches. Parity holds by construction (both evaluate the identical rule data under the same operator semantics) and is confirmed empirically; the same policies also serve from a live \texttt{opa run --server} instance queried over OPA's REST Data API. The portable boundary is the rule-evaluation layer (S3/S4/S6, \S\ref{sec:framework}); the fact transformer (S5---BM25 domain inference and VerbNet action classification) runs once upstream and supplies both engines the same typed predicates. This earns the claim of \S\ref{sec:trac}: we contribute no novel rule-\emph{engine} machinery---the engine is a commodity, the policy and its task-relational predicate are the artefact. Benchmarking the \emph{performance} cost of the OPA substrate is the remaining follow-up (\S\ref{sec:future_work}).

\subsection{Independent Replication of ASTRA's LLM-ResM Benchmark}
\label{sec:astra_replication}

Under Convention~B (ASTRA permissivity view) we recompute classification metrics on E4 from the per-row logs. Our gpt-4o E4 reaches $F_1 = 0.595$ against ASTRA's published $0.67$, a gap of $0.075$ $F_1$ under a strictly harder protocol: ASTRA evaluates per-tool and AND-aggregates the three per-tool verdicts to a bundle decision, whereas we use a single per-bundle call. AND-aggregation systematically inflates precision (any single ``no'' vetoes the bundle), so our number is the expected lower bound. The precision-recall signature replicates exactly: high precision ($0.740$ vs.\ ASTRA's $0.81$), low recall ($0.497$ vs.\ $0.57$), under-scoping dominant. The two additional panel models bracket gpt-4o (gpt-3.5-turbo-16k $F_1 = 0.756$, gpt-5.4 $0.688$)---a successful reproduction of ASTRA's under-scoping finding, not a refutation.

\subsection{Non-Monotone LLM-Only Behaviour with Model Recency}
\label{sec:newer_not_better}

A clean side-effect of the three OpenAI generations: LLM-only (E4) safety is \emph{non-monotone} in recency---gpt-3.5-turbo-16k (2023, $F_1\!=\!0.756$) beats both gpt-4o (2024, $0.595$) and gpt-5.4 (2026, $0.688$). We cannot causally attribute this to RLHF helpfulness without a controlled fine-tune, but the lesson holds across vendors---every $2026$ model we test is a \emph{more} permissive validator than the 2023 model (\S\ref{sec:cross_vendor})---so \emph{a single-LLM validator cannot be assumed to improve as base models advance}.

\subsection{Which Layers Are Load-Bearing: RBAC and TRAC Carry the Load}
\label{sec:reversal}

We measure each layer's contribution two ways. The order-dependent \emph{successive} deltas (E1$\to$E2$\to$E3) are large for every layer---removing RBAC first raises validation SecFail $20.7$pp, then removing ABAC a further $23.4$pp, leaving the TRAC-only floor at $54\%$; selection is larger still ($\Delta_{\mathrm{RBAC}}\!=\!-30.3$pp, $\Delta_{\mathrm{ABAC}}\!=\!-22.9$pp from selection E1 $0.800$/$0.219$, TRAC-only $75\%$). But the honest per-layer measure is the order-independent \emph{drop-one} marginal (SecFail of the full stack vs.\ the stack with exactly that one layer removed). Here the picture sharpens: RBAC ($-20.7$pp) and \textbf{TRAC ($-12.0$pp)} are each individually load-bearing, whereas \textbf{ABAC's drop-one marginal is only $-0.9$pp}---because ABAC and RBAC \emph{overlap}: most attribute violations ABAC would catch are already caught by RBAC. ABAC is therefore a \emph{backstop}: near-redundant given RBAC on this benchmark, but load-bearing when RBAC is absent (its $-23.6$pp successive delta is exactly that regime).

Two readings follow. First, TRAC's isolated $-12.0$pp is direct evidence that the task-relational axis catches violations conventional RBAC$+$ABAC cannot---the core novelty claim, measured rather than asserted. Second, the successive-vs.-drop-one gap for ABAC is a concrete instance of the attribution pitfall of \S\ref{sec:attribution_paradox}: a layer can look essential under one convention and near-redundant under another, so both must be reported. The practical guidance is thus not ``never drop a layer'' but ``RBAC and TRAC are individually load-bearing; ABAC hedges RBAC.'' This also corrects the earlier oracle-aided policy, in which an alignment score did most of the validation work and RBAC/ABAC were near-redundant; removing the oracle redistributes the security load onto identity and the task-relational predicate---exactly where a zero-trust deployment can audit it.

\textbf{Is RBAC's marginal a label artefact?} The RBAC grants are the same persona--domain map that defines the positive class (\S\ref{sec:conventions}), so RBAC's cross-domain marginal could be inflated by construction. We test this by re-authoring RBAC \emph{independently} of the label---coarse job-function roles that \emph{over-provision} relative to the fine-grained allow-list, as real deployments do---and recomputing the marginals (deterministic; labels and the ABAC/TRAC layers held fixed, only RBAC changed). RBAC's drop-one marginal shrinks but stays material ($-20.7\!\to\!-11.3$pp), while the slack redistributes onto TRAC ($-12.0\!\to\!-21.5$pp) and ABAC ($-0.9\!\to\!-9.1$pp), and the floor degrades \emph{gracefully} (SecFail $10.3\!\to\!19.7\%$, at a \emph{lower} $37\%$ false-block). So RBAC is not a pure label artefact, and no single layer's exact tuning is load-bearing---as RBAC loosens, the task-relational predicate absorbs the difference. The exact $10.3\%$ floor benefits from label-aligned RBAC; its \emph{existence} as a model-invariant bound, and TRAC's marginal, do not.

\textbf{A label independent of every policy.} We can go further and decouple the \emph{label} itself from all policy---redefining legitimacy from ASTRA's tag alone (\texttt{is\_legitimate}$=$\texttt{match\_tag}$=$\texttt{correct}, dropping the persona--domain criterion) and recomputing. RBAC's drop-one marginal then falls $-20.7\!\to\!-14.7$pp, while \textbf{TRAC's \emph{rises} to $-17.2$pp, the largest of the three}: under a label no policy artefact authored, the task-relational predicate is the \emph{most} load-bearing layer---the opposite of a circularity artefact.

\textbf{Is TRAC informative, or just more denials?} On the RBAC$\wedge$ABAC-approved set (the $2{,}206$ bundles, $\approx$half illegitimate, where only a task-relational signal discriminates), a \emph{volume-matched random denier} would catch $\approx\!406$ violations while blocking $\approx\!403$ legitimate bundles; TRAC, denying the same volume, catches $597$ and blocks only $212$ (precision $0.74$ vs.\ base rate $0.50$, $1.47\times$)---Pareto-better on both axes. The marginal is task-relational signal, not added volume.

\textbf{The enforcing surface is not only lexical.} Two TRAC rules reason about \emph{action semantics} rather than text overlap: \texttt{action\_coherence} (a read-intent task that selected mutating tools) and \texttt{write\_safety} (a destructive op without a preceding verifying read). Making \texttt{action\_coherence} enforcing catches $39$ same-domain violations that the BM25 predicates and RBAC$+$ABAC all miss, at precision $0.62$---$1.69\times$ the approved-set base rate ($0.37$)---lowering SecFail $10.3\!\to\!9.5\%$ at $+1.2$pp false-block. The enforcing surface thus extends beyond BM25 to structural action coherence. (\texttt{write\_safety} is weaker---precision $0.31$, below base rate---so we keep it advisory.)

\subsection{The Attribution Paradox}
\label{sec:per_domain}
\label{sec:attribution_paradox}

Marginal necessity and first-firing attribution disagree sharply. Attributing every E1 denial to the first layer that fires under short-circuit order (RBAC$\to$ABAC$\to$TRAC), RBAC claims $82\%$ of denials, TRAC $15\%$, and ABAC only $4\%$. Yet the marginal picture (\S\ref{sec:reversal}) is the opposite: ABAC, which first-fires on a mere $4\%$ of denials, carries the largest \emph{successive} marginal ($-23.4$pp---removing ABAC once RBAC is already absent), even though its order-independent \emph{drop-one} marginal is only $-0.9$pp. The reason is pipeline order---most rows ABAC would catch are intercepted earlier by RBAC, so ABAC's unique value is invisible to a denial-source chart and surfaces only when RBAC is removed. First-firing attribution, common in the agent-safety literature, therefore systematically misranks layers; both attribution and marginal $\Delta\mathrm{SecFail}$ must be reported.

\subsection{Corroborated Coverage}
\label{sec:corroborated}

The leak-free domain classifier (\S\ref{sec:domain_inference}) is intentionally imperfect: a business-phrased task can route to a lexically-similar but wrong MCP, so \texttt{capability\_coverage} occasionally denies a correct, in-domain bundle. \emph{Corroborated coverage} reverses such a denial when an \emph{independent} signal---the mean BM25 relevance of the selected tools to the task---is high ($\geq\!4.0$): a legitimate, domain-mis-routed bundle still has tools that lexically match the task, whereas a genuinely wrong-domain bundle does not. Over the model-independent validation profile, enabling the rescue cuts TRAC's unique over-denials of legitimate work from $242$ to $231$, at a cost of $+0.04$pp SecFail and two lost catches---a small Pareto refinement (the sweep knee is $4.0$) that reintroduces no oracle.

\subsection{Dataset Ceiling and Post-Hoc Enforcement}
\label{sec:ceiling}

The $39.1\%$ exact-match number is intrinsically low. Four dataset properties cap performance independently of model capability: (i) tool-naming pedantry across $194$ non-standardised identifiers (the Jaccard$\to$exact-match gap $0.624\!\to\!0.391$); (ii) multiple defensible bundles scored against a single gold; (iii) cross-persona ambiguity over six personas; and (iv) missing bundle-size signal (a single missing tool drops exact-match to $0$). Conservatively the practical ceiling sits at $30$--$40\%$; Jaccard is the less-misleading progress signal.

\textbf{Post-hoc enforcement.} The selection-mode E1$\to$E3 columns of Table~\ref{tab:raicl_security} confirm the deterministic stack does not alter the LLM's selections: tool exact-match and Jaccard are recorded per row before policy gating, so within-cell SecFail differences are purely policy-attributable---PALADIN is a true post-hoc enforcement layer.

\section{Discussion}

\subsection{Operating Point, Policy Dependence, and Generalisability}
\label{sec:deployment_envelope}
\label{sec:policy_dependence}

The headline E1 SecFail of $10.3\%$ carries an availability cost, but measured against the right baseline it is far smaller than a naive count suggests. Reporting the fraction of \emph{all} benchmark-correct bundles the stack denies---a \emph{domain-level} false-block of $\approx\!55\%$---contradicts our own thesis (\emph{correct} $\neq$ \emph{authorised}): a correct bundle invoking a tool the persona is not granted is \emph{inadmissible} by least-privilege, so denying it is the stack working as intended, not a false block. Precisely $44.5\%$ of the denied correct bundles are these correct-but-\emph{unauthorised} requests (RBAC$\wedge$ABAC), which any tool-granular system rejects by design. The availability cost proper is over-denial of \emph{admissible} requests---both benchmark-correct \emph{and} authorised---on which the floor over-blocks $19.3\%$, entirely from the task-relational layer's two BM25 predicates (\path{capability_coverage} $160$, \path{tool_relevance} $52$); RBAC and ABAC contribute \emph{zero} here by construction. Even this residual is partly an inference artefact: an \emph{oracle} domain (\path{domain_source=gold}) lowers it to $14.0\%$, so $\sim\!5$pp is recoverable router error and $\sim\!14$pp genuine lexical sparsity---the honest price of a deterministic, embedding-free relevance signal. The architecture does not mandate that point: the three exposed knobs in \texttt{policies/trac\_rules.yaml}---the \texttt{capability\_coverage} domain floor, the \texttt{tool\_relevance} BM25 cutoff ($<\!1.0$), and the corroborated-coverage rescue bar ($\geq\!4.0$)---plus the choice of which layers to compose govern the security/availability trade-off (Fig.~\ref{fig:operating_sweep}). The floor is the \emph{max-security} end of a navigable frontier: TRAC in \emph{advisory} mode (RBAC$\wedge$ABAC enforcing) moves the point to SecFail $22.3\%$/false-block $44.5\%$, and a realistically over-provisioned RBAC (\S\ref{sec:reversal}) to $19.7\%$/$37\%$. We recommend advisory-TRAC as an availability-balanced default and the full floor where security is paramount; the knobs are released (\S\ref{sec:future_work}).

The security guarantee is conditional on the authored policy artefacts, but bounded: under the short-circuit, removing any denial rule cannot decrease SecFail, so the per-layer marginals (\S\ref{sec:reversal}) upper-bound the damage from silently disabling a rule family; and because RBAC and TRAC carry large marginals while ABAC backstops RBAC (\S\ref{sec:reversal}), one-layer perturbation degrades gracefully rather than catastrophically.

Out-of-envelope concerns---prompt-injection, MCP supply-chain integrity, output exfiltration, DoS, side channels, NL-response safety---are intended to compose with PALADIN via complementary controls~\cite{liu2024formalizing,zhan2024injecagent,inan2023llamaguard,patil2026sentinelagent,gupta2025security,jamshidi2025securing}.

\subsection{The Floor's Adversarial Limit, Quantified}
\label{sec:adversarial}
The threat model (\S\ref{sec:threat_model}) trusts task-text provenance; because TRAC's two enforcing predicates are BM25 over that text, an adversary who controls it can evade them, and we quantify the exposure directly (deterministic, no model). For each \texttt{wrong}/\texttt{null} bundle we append the bundle's \emph{own} tool names and descriptions to the task text---a naive prompt-injection-style padding---and recompute the enforcing predicates: TRAC's catch rate on the $578$ bundles it is designed to stop collapses from $57.1\%$ to $0.0\%$ (\texttt{wrong} $47.7\!\to\!0$, \texttt{null} $94.8\!\to\!0$), because the padding makes the inferred domain snap to the bundle's own and tool-relevance saturate. This is a \emph{measured boundary}, not a surprise: the floor guards \emph{semi-honest mis-scoping} only and composes with prompt-injection defences (\S\ref{sec:threat_model}); the durable contributions---the \emph{measurement framework} and layer analysis---hold regardless.

\section{Conclusion}
\label{sec:conclusion}

Autonomous agents have turned the tool-invocation boundary into a security surface the Model Context Protocol leaves ungoverned, and the prevailing question---\emph{is the model safe?}---is the wrong one. A model's unaided judgment is neither stable nor monotone in capability: across our panel, ungoverned tool admission ranges from a competent validator (gpt-4o, E4 $F_1=0.760$) to a near-yes-machine that lets two-thirds of adversarial bundles through (gpt-5.4, E4 SecFail $=0.665$)---an $F_1$ span of $0.28$ with no ordering by model recency. The operative question is what must be enforced \emph{before} the call, regardless of which model authored the request---and our central result is that a thin \emph{deterministic} admission layer answers it, holding $F_1$ at $0.848$ \emph{identically across every model} because it never consults one. The guarantee is a property of the stack, not of the LLM.

Our measurement framework is built to show this rather than assert it. By separating what the model contributes from what the policy contributes---through dual-mode evaluation and two explicit metric conventions---it makes the masking effect measurable, and in doing so surfaces structure prior task-tool benchmarks could not: three deterministic layers each carrying large marginal weight in both modes, first-firing attribution that overstates upstream necessity while hiding ABAC as the irreplaceable backstop, and a retrieval intervention that improves accuracy and security together. PALADIN contributes a task-relational admission primitive within a security-first floor---not a complete new access-control model, nor an end-to-end agent-safety solution. Its lesson for the agentic era is a single design principle: authorisation must not ride on model trustworthiness. Determinism, not capability, is what turns an unpredictable model into a predictable security surface.
